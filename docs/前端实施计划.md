# 原神风格前端页面 · 实施计划

> 目标：为现有 FastAPI 后端添加一个**原神（Genshin Impact）风格**的前端页面，复用 `图片/` 文件夹中的角色素材，实现注册 / 登录 / 待办管理完整交互。
>
> 本计划基于当前项目代码逐文件分析，可直接按阶段执行。

---

## 一、现状分析

### 当前项目状态
- 后端：FastAPI，仅提供 JSON API（`/auth/*`、`/todo/*`）和 Swagger（`/docs`）。
- **没有任何前端页面**：访问 `http://127.0.0.1:8000/` 返回 404。
- **没有静态文件托管**：`main.py` 未挂载 `StaticFiles`。
- **没有 CORS 配置**（当前不需要，因为前端将与后端同源部署）。

### 素材盘点（`图片/` 文件夹，尺寸已实测）
| 文件 | 尺寸 | 形态 | 建议用途 |
|------|------|------|----------|
| `95292a9b...jpg` | 1080×778 | 横版横幅 | 登录页/顶部的**主视觉横幅背景** |
| `旅行者.png` | 490×1214 | 全身立绘（透明底PNG） | 登录页**侧边装饰立绘**（透明底，可直接叠加） |
| `甘雨.jpg` | 712×1804 | 全身立绘 | 待办页**左侧装饰立绘** |
| `芭芭拉.jpg` | 640×929 | 竖版角色 | 待办页**右侧装饰立绘** |
| `八重神子.jpg` | 500×500 | 方图 | **用户头像** / 登录卡片装饰头像 |

### 技术可行性（已实测确认）
- `fastapi.staticfiles.StaticFiles` 在 starlette 0.38.6 下可用，**无需安装 aiofiles**。
- 前端与后端同源（都由 uvicorn 8000 端口提供），**无需 CORS 配置**。
- 前端用**纯 HTML/CSS/JS（原生，零构建）**即可完成，与现有 Docker 部署完全兼容（`COPY . .` 已包含新目录）。

### 字体与质感

- 正文：`"Noto Sans SC", "Microsoft YaHei", sans-serif`。
- 卡片：圆角（12-16px）、细金边（`1px solid rgba(201,168,106,0.5)`）、柔和阴影。
- 装饰：星空/四芒星小元素（CSS 绘制或 SVG）、渐变横幅底部叠加。

- 401 处理：token 失效自动跳回登录视图并提示。

## 四、API 对接要点（前端最容易踩的坑）

| 接口 | 方法 | 请求体格式 | 关键点 |
|------|------|-----------|--------|
| `POST /auth/register` | JSON | `{"username","password"}` | 用 `JSON.stringify`，`Content-Type: application/json` |
| `POST /auth/login` | **表单** | `username=..&password=..` | **必须用 `URLSearchParams` / `FormData`**，不能用 JSON，否则 422 |
| `POST /todo/` | JSON | `{"title","description"}` | 带 `Authorization: Bearer <token>` |
| `GET /todo/?page_num=&page_size=` | 查询参数 | — | 返回 `{code,msg,data:{list,total,...}}` |
| `PUT /todo/{id}` | JSON | `{"title"?,"description"?,"is_done"?}` | 字段可空，只传要改的 |
| `DELETE /todo/{id}` | — | — | 成功返回 `code:200` |
| `DELETE /todo/clear` | — | — | 清空当前用户 |

- **统一响应判断**：所有接口成功都是 HTTP 200 + `code:200`；业务错误 `code:400`（如"用户名已存在"）；401 时后端返回 HTTP 401（需跳登录）。
- **token 存储**：`localStorage.setItem("token", ...)`；`api.js` 统一在请求头加 `Authorization: Bearer`。
- **登录后**：存储 token + 用户名 → 切换到待办视图并加载第一页。

## 五、分阶段实施步骤

### 阶段 0：静态服务搭建（约 10 分钟）
1. 创建 `static/` 目录结构（css/js/images）。
2. 从 `图片/` 复制 5 张图到 `static/images/` 并规范命名。
3. 修改 `main.py`：
   ```python
   from fastapi.staticfiles import StaticFiles
   from fastapi.responses import FileResponse

   app.mount("/static", StaticFiles(directory="static"), name="static")

   @app.get("/", include_in_schema=False)
   async def index():
       return FileResponse("static/index.html")
   ```
4. 写一个最小 `index.html`（只显示"Hello"）。
5. **验证**：重启服务 → 浏览器打开 `http://127.0.0.1:8000/` 能看到页面；`http://127.0.0.1:8000/static/images/traveler.png` 能显示图片。

### 阶段 1：登录 / 注册功能（约 30 分钟）
1. `api.js`：封装 `login()`、`register()`、`request()`（统一带 token、统一解析 `{code,msg,data}`）。
2. `app.js`：视图切换逻辑（`showView('login')` / `showView('todo')`）。
3. 登录表单：`URLSearchParams` 提交 → 成功存 token → 进待办视图；失败显示 `msg`。
4. 注册表单：JSON 提交 → 成功后自动切到登录（提示"注册成功，请登录"）。
5. **验证**：浏览器注册新用户 → 登录 → 进入待办视图。

### 阶段 2：待办主页面功能（约 40 分钟）
1. 新建待办：表单 → `POST /todo/` → 刷新列表。
2. 列表渲染：`GET /todo/?page_num=&page_size=` → 渲染卡片列表（标题/描述/时间/状态）。
3. 勾选完成：`PUT /todo/{id}` 传 `is_done`。
4. 编辑：弹窗/内联 → `PUT /todo/{id}` 传改动的字段（`exclude_unset` 语义：只传要改的）。
5. 删除单个：确认 → `DELETE /todo/{id}`。
6. 清空全部：二次确认 → `DELETE /todo/clear`。
7. 分页：上一页/下一页 + 总页数显示。
8. 退出登录：清 localStorage → 回登录视图。
9. **验证**：完整走一遍增删改查 + 分页 + 退出。

### 阶段 3：原神风格美化（约 40 分钟）
1. 按第三节设计规范写 `style.css`：
   - 登录页横幅背景（banner.jpg，`background-size: cover` + 渐变遮罩）。
   - 旅行者立绘置于表单左侧（PNG 透明底直接叠加）。
   - 待办页左右两侧固定立绘（甘雨/芭芭拉，`position: fixed` + 低透明度）。
   - 玻璃卡片、金色描边、圆角、衬线标题。
   - 用户头像圆形裁切（八重神子）。
2. 加细节：按钮 hover 效果、待办完成动画、加载提示、空列表提示。
3. **验证**：不同分辨率下布局正常（1280 宽为主，窄屏隐藏侧边立绘）。

### 阶段 4：联调与收尾（约 20 分钟）
1. 全流程回归：注册 → 登录 → 增删改查 → 退出 → 重新登录。
2. 边界测试：错误密码提示、token 过期跳登录、清空确认。
3. 更新 `README.md`：加前端说明、页面截图、`图片/` 素材说明。
4. 提交 GitHub：`git add static/ docs/前端实施计划.md` → commit → push。
5. **验证清单**（逐项打勾）：

   - [ ] 注册新用户成功

## 六、风险与注意事项

| 风险 | 说明与对策 |
|------|-----------|
| 图片体积 | 芭芭拉 836KB / 旅行者 586KB，页面加载稍慢。对策：装饰图用 `loading="lazy"`；必要时后续压缩 |
| 中文路径/长文件名 | `图片/` 文件夹不宜直接作为静态目录（URL 编码中文、超长文件名）。对策：已规划复制到 `static/images/` 规范命名 |
| 登录接口格式 | 前端用 JSON 提交登录会 422。对策：api.js 中登录固定用 `URLSearchParams` |
| token 安全 | localStorage 有 XSS 风险（本项目纯前端无用户输入注入面，风险可控）；进阶可换 HttpOnly Cookie |
| 路由冲突 | `GET /` 与现有 API 无冲突；`/static` 挂载在路由之后注册即可，不影响 `/auth`、`/todo` |
| 部署 | Docker `COPY . .` 已包含 `static/`；`图片/` 若不想进镜像可后续调整 .dockerignore |

## 七、技术选型说明（决策点）

**推荐：原生 HTML/CSS/JS（零构建）**
- 优点：无 Node 工具链、与 Docker/现有部署零冲突、学习价值高、文件少。
- 适合：当前项目规模（3 个视图、1 个列表页）。

**备选 A：Vue 3（CDN 引入，无构建）**
- 优点：响应式语法更简洁（`v-for`、`v-model`），后续扩展（多页面/组件化）更轻松。
- 缺点：依赖 CDN（离线部署需本地化 vue.global.js）。

**备选 B：Vue/React + Vite（构建工具链）**
- 优点：工程化、组件化、热更新。
- 缺点：需要 Node 环境、构建产物需整合进 FastAPI 静态目录，Dockerfile 也要改（多阶段构建），复杂度明显上升。

> **本计划默认按"原生 HTML/CSS/JS"执行**；如你倾向 Vue CDN 或 Vite，仅影响阶段 1-3 的写法，文件清单与接口对接不变。
